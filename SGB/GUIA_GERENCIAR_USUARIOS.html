🗄️ NÍVEL 1: Banco de Dados

Arquivo: SGB/Database/schema.sql

O que mexer?

  • ✅ Tabela Usuarios já tem coluna Ativo (perfeito!)
  • ✅ Adicionar índices para otimizar queries de filtro

SQL a Adicionar

Cole este código ao final do arquivo schema.sql:

-- Índices para performance na tabela Usuarios IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'IX_Usuarios_Email' AND object_id = OBJECT_ID('dbo.Usuarios')) BEGIN CREATE INDEX IX_Usuarios_Email ON dbo.Usuarios (Email); END GO IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'IX_Usuarios_Ativo' AND object_id = OBJECT_ID('dbo.Usuarios')) BEGIN CREATE INDEX IX_Usuarios_Ativo ON dbo.Usuarios (Ativo); END GO

✅Resultado

Estes índices melhoram a performance das queries que filtram por email ou status ativo/inativo.

⚠️ Cuidados Importantes

1. Validar Email Duplicado

PROBLEMA: Dois usuários podem ter o mesmo email!

SOLUÇÃO: Antes de fazer UPDATE, verifique se o email já existe:

private bool VerificaEmailDuplicado(string email, int usuarioIdExcluir = 0) { string sql = @"SELECT COUNT(*) FROM Usuarios WHERE Email = @email AND Ativo = 1"; if (usuarioIdExcluir > 0) sql += " AND Id != @id"; var dt = ConexaoBanco.ExecutarConsulta(sql, new SqlParameter("@email", email), new SqlParameter("@id", usuarioIdExcluir)); return Convert.ToInt32(dt.Rows[0][0]) > 0; }

2. Não Permitir Inativar a Si Mesmo

PROBLEMA: Um admin pode se inativar e ficar preso!

SOLUÇÃO: Já implementada no código acima ✅

3. Validar Permissão de Acesso

PROBLEMA: Qualquer usuário pode editar outros usuários!

SOLUÇÃO: Já implementada no evento Load() acima ✅

4. Não Permitir Editar Email Vazio

if (string.IsNullOrWhiteSpace(txtEmail.Text) || !txtEmail.Text.Contains("@")) { MessageBox.Show("Email inválido!"); return; }

5. Registrar Modificações (Auditoria)

RECOMENDAÇÃO: Criar tabela de auditoria para registrar quem alterou o quê (funcionalidade futura)
